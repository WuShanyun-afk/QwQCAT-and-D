# 小D 桌宠 · dsh-desktop-pet 🐾

在 Windows 桌面上的一只小D：透明背景、永远在最上层、会跟着鼠标跑，还会说话。

## 怎么玩

双击 **`启动小D桌宠.bat`** 就行（用 `pythonw` 启动，不会留黑窗口）。

| 操作 | 效果 |
| --- | --- |
| 鼠标移动 | 小D 会跑过去，站在鼠标旁边（走到鼠标右边，右边放不下就走左边） |
| 左键拖动 | 把小D 拎起来放到任意位置 |
| 双击 | 冒爱心 + 说一句随机台词 |
| **右键** | 菜单：跟着鼠标跑 / 待在角落 / 睡觉·起床 / 说句话 / 退出小D |

透明区域是**点得穿的**，不会挡住后面的窗口。

## 我在 DSH 里怎么跟它说话

改这个文件的内容（UTF-8）：

```
我的插件/dsh-desktop-pet/say.txt
```

小D 会每 ~30ms 检查一次，一改内容就在气泡里念出来（最多 80 字）。
所以以后我在 DSH 里写完，你可以直接看到桌宠开口说话。

## 文件

| 文件 | 说明 |
| --- | --- |
| `pet.py` | 主程序（tkinter + Pillow，透明窗口用洋红键控） |
| `生成素材.py` | 从 `小D/拆分图/成品-透明底/` 的三帧生成 `assets/{idle,wink,blink}.png`（对齐裁切 + 底部柔化渐隐） |
| `assets/character.png` | 形象图（妈妈画的小D人设·正面全身，透明底） |
| `say.txt` | 我写字 → 桌宠念出来 |
| `pet-config.json` | 自动记住位置和模式 |
| `启动小D桌宠.bat` | 双击启动 |

## 现在这版会什么

- **只有尾巴会摇**：全身不动、耳朵也不动（妈妈说耳朵也不要用动），尾巴慢慢左右摆，待机时 4 个姿态循环

- 我在 DSH 里改 `say.txt`，它就在气泡里念出来

## 技术备注

- 透明窗口：`-transparentcolor` + 洋红键控（硬边裁剪，alpha ≥ 110 保留）
- **透明像素是点得穿的**，所以只能点到角色实体部分
- 单击/双击区分：按下→抬起位移 ≤6px 且 <0.45s 才算单击，**延迟 220ms 等双击确认**
- 状态机（优先级从高到低）：`PET_DEBUG_STATE` > 摸头 `blink(笑眼)` > 双击 `wink` > 夜里 `wink/blink` > 白天 `blink/idle`
- 帧：`assets\{idle,wink,blink}_{0..3}_{0..1}.png`，按需加载并缓存（洋红键控后才进 PhotoImage）
- 调试开关：环境变量 `PET_FORCE_NIGHT=1` / `PET_FORCE_DAY=1` / `PET_DEBUG_STATE=idle|wink|blink`
- 不装任何额外依赖（系统 Python + Pillow；声音用自带的 winsound 放 wav）
- 关掉 DSH 不影响桌宠；它自己是独立进程

## 2026-10-20 晚（第三版）：只动耳朵和尾巴 + 点击弹一下「吱吱」

妈妈原话：「不全身动 让耳朵和尾巴抖动就好了，最好还可以点击小D桌宠会浑身弹一下发出吱吱的响声，冒爱心emoji弹颜文字，但是只弹一两个。」

1. **去掉全身摇摆**：以前整张图 ±1.5° 左右晃，现在身体完全静止；改成
   - **尾巴摇**：**直接用妈妈画的 `15-尾巴` 图层当精灵**（不是从成品图上切一块），绕尾根 (700,1150) 旋转 4 个角度（-6.5° / -2.2° / +2.2° / +6.5°），按 sin 曲线循环
   - **耳朵不动**（2026-10-20 晚妈妈说「耳朵也不要动了」）：`EAR_ANGLES = (0.0,)` 只渲 1 帧，耳朵保持原样，`pet.py` 里 `ei` 恒为 0
   - 左蓝猫耳只在成品图里有（分层件没有），所以左耳跟着头发不动，只抖右耳 —— 反而自然
2. **点击反应**：整只弹一下（`canvas.coords` 上下 -9px×2 弹跳）+ **「吱吱」声**（`assets/squeak.wav`，用 numpy 合成两声短鸣，`winsound` 异步播放）+ **只冒一两个**：一颗爱心 emoji + 75% 概率一个颜文字，1.5 秒飘走
3. 关键坑：**气泡会把角色 `tag_raise` 到最上层**，所以粒子必须最后添加（否则被角色挡住看不见）
4. 关键坑：颜文字别用 `๑ ㅂ ᴗ` 这些字，微软雅黑没有 → 显示成方块；只用 `(≧▽≦) (*/ω＼*) (｡>﹏<｡) ヾ(≧▽≦*)o (>ω<) (＾▽▽)`
5. 帧的生成（`生成素材.py`，跑一次约 8 秒）：
   - 尾巴、耳朵精灵**直接取自妈妈的分层图**，绕根部旋转；不再从成品图上「切一块」下来；
   - 身体 = 成品图，**只把露在身体轮廓外的尾巴/耳朵抠掉**（尾巴底下是天空 → 透明；耳朵压在头发上的根部 → 用外圈头发中位色 (38,55,81) 补平，不会露洞）；
   - 合成顺序：尾巴（最底）→ 耳朵（也在身体后面，耳根被头发盖住，转动才不露缝）→ 身体；
   - 24 帧 = 3 状态 × 4 尾巴 × 2 耳朵，统一裁切到 340 高 + 底部 4.5% 渐隐。
   - ⚠️ 踩过的坑：耳朵一开始画在身体**前面** → 转动时耳根露白缝、像贴上去的；改成画在身体**后面**（跟真画法一致）就自然了。
6. ⚠️ `Set-Content -Encoding UTF8` 会把中文源码写成乱码（GBK 读 UTF-8）——**改 .py 用 edit/write 工具，别用 PowerShell 重新编码**。

## 2026-10-24 深夜：1:1 渲染 & 白边体检（结论：本来就是 1:1，现在没有白边）

交接备忘里留过一句「125% 缩放下桌宠实际是 0.8 倍（窗口 272×344、画布 340×430），边缘可能还有极细白边」。
这次查清楚了，**两条都是误会**，记下来免得下一个我又白折腾：

1. **0.8 倍是「测量工具」的假象，不是桌宠的缩放。**
   - `pet.py` 开屏就 `SetProcessDpiAwareness(2)`；在 125% 屏幕上窗口是 **340×430 物理像素**、canvas 也是 340×430，素材帧高 340，**贴上去 1:1、没有任何缩放**。
   - 同一个窗口，用**不带 DPI 感知**的进程去 `GetWindowRect`，量到的就是 **272×344**（= 340×0.8）——因为 GDI 把它虚拟化成了 96 DPI 坐标。之前那句「0.8 倍」就是这么来的。
   - 实锤：屏幕截图（DPI 感知）和 `assets`/`outfits` 键控后的帧**逐像素比对，62,227 个不透明像素 0 个不同**。
2. **当前四套衣服（常服 / 睡衣 / 白大褂 / 白大褂·眼镜）都没有白边。**
   - 16 张 idle 帧的「轮廓边缘像素」（不透明且贴着透明背景）亮度：中位数 43~53（深色描边），最亮 165/255，**亮度 >200 的个数 = 0**。
   - 洋红键控是硬阈值（alpha ≥ 60），但 `工具/桌宠素材.py` 生成时已经把外圈压成深色描边、并做过「边缘渗色」，所以键控不会切出白边。
   - 点击「电子捏捏乐」的缩放帧也单独量过：贴边浅色像素 0~1 个（可忽略）。
3. **以后想复查，用 `python 工具\截桌宠.py`**（系统 Python + Pillow 就够，不需要 numpy）：
   - 它先 `SetProcessDpiAwareness(2)`，再 `PrintWindow` 抓窗口真实内容，打印「窗口大小 / DPI / 轮廓边缘最亮多少 / 有没有 >200 的白边像素」的结论，并存一张 1:1 截图（`--zoom 6` 另存 6 倍放大图）。窗口内容里透明处是黑底，所以白边会非常显眼。
   - ⚠️ 桌宠正在**说话**时，白色气泡也会被算成「边缘」：工具会自动判断「亮像素是不是都挤在上方气泡区」，是的话结论会写「是气泡不是白边」。想量干净就等气泡消失再跑。
   - 这次体检的对比图：`备份/桌宠边缘体检-2026-10-24.png`（白 / 深灰 / 黑三种桌面 + 6× 放大）。
4. `pet.log` 启动时多了一行 `start dpi=120 win=340x430 frame_h=340`，交接自检时一眼就能确认是 1:1、没被系统缩放。
5. 如果哪天**真的**又看到白边：先用上面的工具抓 1:1 图确认，再考虑把洋红键控换成**真 per-pixel alpha 的层叠窗口**（`UpdateLayeredWindow`）——那是唯一能连半透明边缘一起做对的路子，但要重写画布层，成本高，非必要不做。
